# P2-19 — SocialFlow AI + LinkedIn Provider Isolation

## Scope
- Move runtime ownership of SocialFlow AI and LinkedIn provider flows into `apps/socialflow-runtime/*`.
- Keep the canary inactive.
- Keep the active monolith runtime, production worker, DNS, deploy and traffic unchanged.

## Ownership moved

### AI runtime
- `apps/socialflow-runtime/src/lib/socialflow/ai/contracts.ts`
- `apps/socialflow-runtime/src/lib/socialflow/ai/provider.ts`
- `apps/socialflow-runtime/src/lib/socialflow/ai/orchestrator.ts`
- `apps/socialflow-runtime/src/lib/socialflow/ai-service.ts`

The runtime now generates campaigns and post regenerations through a local orchestrator that:
- builds profile context from the runtime-owned profile store,
- derives competitor, trend, keyword, strategy and optimization steps locally,
- persists campaigns and posts via runtime-local repositories,
- no longer imports `@/lib/socialflow/ai/*`.

### LinkedIn provider runtime
- `apps/socialflow-runtime/src/lib/socialflow/linkedin/types.ts`
- `apps/socialflow-runtime/src/lib/socialflow/linkedin/core.ts`
- `apps/socialflow-runtime/src/lib/socialflow/linkedin/client.ts`
- `apps/socialflow-runtime/src/lib/socialflow/linkedin/repository.ts`
- `apps/socialflow-runtime/src/lib/socialflow/linkedin/publishing.ts`
- `apps/socialflow-runtime/src/lib/socialflow/linkedin/oauth.ts`
- `apps/socialflow-runtime/src/lib/socialflow/linkedin-service.ts`
- `apps/socialflow-runtime/src/lib/socialflow/live-publishing-service.ts`

The runtime now owns:
- OAuth state parsing and callback resolution,
- LinkedIn token exchange and profile fetch,
- runtime-local LinkedIn account persistence in `saas_social_accounts`,
- runtime-local LinkedIn publishing and validation,
- runtime-local callback handling without monolith observability or integration-core coupling.

## Remaining shared references
- `@/lib/auth/crypto`
- `@/lib/cloudflare/runtime`

These remain in `SAFE_SHARED_PACKAGE`, not `TEMP_SHARED`.
